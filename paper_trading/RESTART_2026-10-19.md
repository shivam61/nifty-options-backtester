## (c) Logging a SKIP day

Row format for a skip (monthly columns are 0 in Phase 1; YTD columns blank until the first real trade):

```
2026-10-19,Monday,2500000,0,0,<VIX>,<regime>,0,0,0,0,0,,,"SKIP <CODE>: <one-line reason>"
```

- `Weekly_Opportunities_Eligible` = 1 if the weekly track printed a suggested trade, else 0.
- `Weekly_Trades_Executed` = 0 on a skip.
- `Market_Regime` = the `Regime:` value in the RISK ENGINE ASSESSMENT line, or `rule-based` if no engine loaded.
- Quote the Notes field if it contains a comma.

## (e) Exit rules recap

| Rule | What it means | Source |
|------|---------------|--------|
| **Profit target** | PCS: 75% of max profit (the CLI prints the ₹ amount). IC: none. | `config.py` `engine_a_profit_target_pct = 75`; signal printout |
| **Stop loss (only stop rule)** | Loss reaches 100% of credit collected, **or** price breaches the short strike. Exit immediately. | `config.py` `stop_loss_pct = 100`; signal printout |
| **Expiry** | Hold to expiry or exit earlier. Operator practice: close by 15:15 IST on expiry day. | Original template |
| **Max hold / min hold** | The signal prints: PCS "Min Hold 2 trading days"; IC "Max Hold 4 trading days". **There is no 3-day cap.** | Signal printout. IC 4-day max hold: proposed, pending owner confirmation (open question 1) |
| **Account pause (only pause rule)** | Account DD ≥ 15% of peak equity (₹3,75,000 from ₹25L). Stop new entries, close open positions, review. | Proposed (audit finding), pending owner confirmation |

**There is no per-trade ₹ cap.** The backtest's worst weekly loss is ₹−53,255, which is above the old ₹50k cap. No ₹ cap is enforced per trade; the 100%-of-credit stop governs.

## (f) Known gaps

1. **Premiums are estimates.** Every signal price is `[BS est]`. The weekly track never uses a Fyers chain. Real bid/ask from the broker is required for any fill.
2. **REST API is down.** `api/server.py` startup calls methods that do not exist (`load_cached`), reads a wrong VIX column (`vix_close`), hardcodes equity, uses a `utcnow` window, and its CSV schema does not match `Journal_ID`. Use the CLI and manual CSVs until fixed. No separate known-issues document exists yet; this list is the known-issues record.
3. **Holiday calendar: fixed in code.** `data/nse_holidays.json` holds the list and `data/expiry_calendar.py` applies it. Verified against NSE's holiday master API on 2026-10-18. Closures: Tue 2026-10-20, Tue 2026-11-10, Tue 2026-11-24.
4. **Expiry shift: fixed in code.** A Mon 10-19 entry selects Tue 2026-10-27 (8 DTE, top edge of the 3-8 window). Confirm the printed expiry before entering.
5. **Models.** Weekly track accepted with the risk engine OFF. Monthly track NOT accepted: the retrained entry model produced 0 monthly trades in the backtest and is under investigation. Ignore monthly output.
6. **Fyers clock and credentials: fixed in code.** The live-quote gates used the host UTC clock and could not fire in the 11:00-13:00 IST window; they now use IST. Credentials are read from `.env`, then `.env.local` (names only are ever printed).
7. **Backtest pre-2019 is based on BS-estimated premiums**, so it is directional only.
8. **Weekly DTE window (investigated 2026-10-19, code at 4a19a0f).** The 363 "ETL > credit skips" in old backtest logs were fill-time DTE drops (Monday signal at 3 DTE, next-day fill at 2 DTE), not the ETL gate; the live signal checks DTE the same day, so Monday is not affected. A what-if that trusts the signal-time window gave 17.97% CAGR, but every extra trade is pre-2024-04-04, filled at 2 DTE and priced by Black-Scholes only, with about half the expectancy per lot and a worse worst-trade (Rs-9,143 per lot). Default NOT changed (`WeeklyBacktestConfig.dte_check_at_signal=False`). Counters are now `weekly_fill_dte_drops` / `weekly_etl_gate_skips`; the printed "ETL > credit skips" is the real ETL-gate count only. Live rule unchanged: if DTE is outside 3-8, log `DTE_OUT_OF_RANGE`.
